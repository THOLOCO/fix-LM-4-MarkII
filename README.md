# LM-4 MarkII 修复 / Fix

对 Steinberg **LM-4 MarkII**（2003 年发布的 32 位 VST2 鼓采样器）在现代
Windows / DAW 上无法加载的问题做了逆向分析，并给出**可复现**的二进制修补。

> **本仓库不包含任何 DLL 或其它可执行文件。**
> 补丁脚本可以从你自己的原版 DLL 完整复现修补结果。

---

## 修复清单

| # | 症状 | 根因 | 修补位置 |
|---|------|------|----------|
| 1 | 插件加载即崩（宿主报"插件有问题"） | NeoLite 壳解压后把 `.text` 段设为 `PAGE_READWRITE`，现代 DEP 下不可执行 | 文件 `0x3A16` `0x3AA8` `0x3D3C`：`0x04 → 0x40` |
| 2 | 加载失败，但没有任何错误提示 | `main()` 内的安装校验失败后静默返回 `NULL`；错误对话框所需的字符串资源 ID 不存在，`LoadStringA` 失败后跳过 `MessageBoxA` | VA `0x1001B968`：`75 35 → EB 35`（`jne → jmp`） |
| 3 | 分配 MIDI 输入端口后崩溃 / 调整鼓垫参数崩溃 | `0x10016120` 直接解引用 `[this+0x184]`，无空值检查 | VA `0x10016120`：改写为空值安全版本 |
| 4 | 调整鼓垫 Tune 旋钮崩溃 | `0x10014A68` 把 `[this+0x1DC]`（采样管理器）传给 `0x100F4020` 前未判空，而后者首条有效指令即 `mov edx,[ecx+0x2AC]` | VA `0x10014A68`：插入 `jecxz` 保护 |

### 关于问题 1

原 DLL 被 NeoLite 加壳。壳解压完成后用 `VirtualProtect` 把整个 `.text`
设为 `PAGE_READWRITE`。2003 年 32 位进程默认关闭 DEP，所以当年正常；
现代 Windows 全面启用 DEP，跳到入口点即触发访问冲突。

### 关于问题 2

错误提示框本身也弹不出来：代码请求的字符串资源 ID（128）在资源表里
不存在（实际只有 `16496 / 16528 / 16576 / 16640 / 49312`），
`LoadStringA` 失败后 `MessageBoxA` 被跳过 —— 于是变成"静默失败"。

### 关于问题 4

全局 M. Tune 的同款路径（`0x1488E`）**是有**判空的，作者只在鼓垫这条
路径上漏了。这是原程序的一致疏漏，不是环境问题。

## 复现修补

需要自备原版 `LM4-MarkII.dll`：

```
    MD5   29b5a2eaff617264fa589164ed23d4a0
    大小  579,032 字节
```

然后运行：

```bash
python3 04_分析脚本/补丁工具/apply_all_fixes.py LM4-MarkII.dll LM4-MarkII_fixed.dll
```

脚本流程：校验输入 MD5 → 打上全部 6 处补丁 → 重新压缩 `.text` 流 →
校验输出 MD5。预期输出：

```
    MD5   9f48c98171df2efcbf4fbec8901eafef
```

> 仅依赖 Python 3 标准库（`zlib` / `hashlib`），无需第三方包。
> 若脚本提示「原字节不符」，说明你手上的原版与本文档分析的版本不同，
> 请把输入文件的 MD5 反馈出来。

## 单元测试

`04_分析脚本/补丁工具/单元测试_*.py` 使用 Unicorn 模拟 CPU，直接调用被
修补的函数验证行为（含"原版必崩 / 修补后安全"的对照）。

它们需要**解壳后的内存镜像**，该镜像不在仓库内，请自行生成：

```bash
cd "04_分析脚本/模拟器"
python3 emu7.py        # 需要当前目录下有 LM4-MarkII.dll
                       # 产出 unpacked2.bin
```

然后把 `unpacked2.bin` 复制为 `03_内存镜像/unpacked_image.bin`。

依赖：

```bash
pip install unicorn capstone
```

## 环境

- 32 位 VST2 插件，需要 32 位宿主，或用桥接器接进 64 位宿主
- 分析脚本：Python 3
  - 补丁脚本：仅标准库
  - 模拟器：需要 `unicorn` 与 `capstone`

## 已知未修复

- 程序名上限硬编码 20 个（`cmp eax, 0x14`）
- 手动 `Open bank file...` 加载的 `.fxb` 不注册程序名（插件设计如此）
- `0xEDB42` 处工厂返回值缺少 NULL 检查（已在读取端兜底）
