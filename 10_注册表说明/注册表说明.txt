【为什么需要这份文档】

  实测发现：即使使用修补后的 DLL，在某些电脑上插件启动后仍会被
  宿主禁用（提示 processing error，且没有其它报错信息）。
  在这些电脑上导入本插件所需的注册表项后，问题消失。

  因此**分发插件时，除了 DLL 和音色内容，还需要导入注册表**。

----------------------------------------------------------------
一、插件读取哪些注册表项
----------------------------------------------------------------
逆向分析确认（解壳后镜像）：

  键：HKEY_LOCAL_MACHINE\Software\Steinberg\LM4-MarkII
  值：
      SetupID      REG_SZ      由 4 段数字组成的字符串
      SetupSysID   REG_BINARY  10 字节，解码后是一个 10 位数字串

  同时还读取 Windows 自身的 ProductId（一般不需要额外操作）：
      HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\ProductId
      HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion\ProductId

  读取代码位置（供参考）：
      注册表读取封装    RVA 0x1F020
      读 SetupID        RVA 0x1EB70（在 0x1EBAC 调用封装）
      读 SetupSysID     RVA 0x1F0B0（在 0x1E83D 调用封装）

----------------------------------------------------------------
二、SetupSysID 的编码方式
----------------------------------------------------------------
SetupSysID 是 10 字节二进制，解码算法：

    每个字节  b  ->  (b - 8) XOR 1  ->  得到一个字符

反向编码（从数字串生成二进制）：
    每个字符 c  ->  (c XOR 1) + 8

----------------------------------------------------------------
三、实测可用的值（从可用机器直接导出）
----------------------------------------------------------------
以下数据于 2026-09-13 从 **TOLOC-LAPTOP（192.168.3.177）**
用 `reg export` 原样导出，该机插件工作正常：

    SetupID     = 0-0-0-0
    SetupSysID  = 3D 3B 3C 3A 3F 3C 3F 3C 39 3F
                  解码后 = "4253656506"

注意这个值和早期分析时假设的不同（见第六节）。

----------------------------------------------------------------
四、怎么导入
----------------------------------------------------------------
本目录下的 LM4-MarkII_注册表.reg 已包含上述内容，
双击导入即可（需要管理员确认）。

也可以手动：Win+R -> regedit -> 找到
    HKEY_LOCAL_MACHINE\SOFTWARE\Steinberg\LM4-MarkII
新建上述两个值。

注意（64 位 Windows）：
    插件是 32 位程序，在 64 位系统上默认读取 WOW6432Node 视图，
    即实际路径为
        HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Steinberg\LM4-MarkII
    本目录的 .reg 文件同时写入了两个视图，确保两种系统都能读到。

----------------------------------------------------------------
五、如何从一台正常工作的电脑导出
----------------------------------------------------------------
如果上面的值在你的环境里不适用，可以这样做：

  regedit -> 定位到
      HKEY_LOCAL_MACHINE\SOFTWARE\Steinberg\LM4-MarkII
  （64 位系统上如果上面这个位置为空，请看
      HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Steinberg\LM4-MarkII）
  右键该键 -> 导出 -> 保存为 .reg
  把这个 .reg 一起发给别人导入即可。

命令行方式（管理员 CMD）：
  reg export "HKLM\SOFTWARE\WOW6432Node\Steinberg\LM4-MarkII" x.reg /y

----------------------------------------------------------------
六、一个需要说明的疑点
----------------------------------------------------------------
早期分析（从另一台机器的数据）曾得出 SetupSysID 解码后应为
"2523069250"：

    3B 3C 3B 3A 39 3F 40 3B 3C 39  ->  "2523069250"

但 TOLOC-LAPTOP 上实际可用的是：

    3D 3B 3C 3A 3F 3C 3F 3C 39 3F  ->  "4253656506"

两者不同，而后者在实机上插件工作正常。

解释：修补后的 DLL 已经跳过了 main() 里"校验失败就返回 NULL"的
分支（0x1001B968 处 jne 改 jmp），因此**校验结果本身不再决定
插件是否加载**。校验函数仍会被调用（它同时承担初始化工作），
而注册表项**存在**与**完全缺失**会导致它走不同分支、产生不同的
初始化路径 —— 这才是"某些电脑上被禁用"的真正原因。

结论：**分发时应使用实测可用的值**（即本节后半段那组）。
若你的机器用这组值仍不行，请按第五节导出你自己机器的值。

----------------------------------------------------------------
七、同机其它 Steinberg 插件（供对照）
----------------------------------------------------------------
同一台电脑上还装了 Virtual Guitarist 系列，注册表结构完全相同：

    [HKLM\SOFTWARE\WOW6432Node\Steinberg\Virtual Guitarist]
    SetupID     = 1239765930-1066732172-2494725182-359992275
    SetupSysID  = 38 3E 41 38 3A 3E 38 3A 38 38   ("1781371311")

    [HKLM\SOFTWARE\WOW6432Node\Steinberg\Virtual Guitarist EE]
    SetupID     = 2885539254-1066732172-2494725182-359992275
    SetupSysID  = 3D 38 3B 3A 40 38 3B 39 3D 3B
    Install Path= C:\Program Files (x86)\Steinberg\Vstplugins\Virtual Guitarist Electric Edition

可见 SetupID 一般是 4 段 10 位数字，而 LM-4 这台机器上写的是
"0-0-0-0"（安装器/注册机留下的占位值）—— 这也印证了
"值本身不重要、只要项存在"的推断。

【English】

----------------------------------------------------------------
Why this document exists
----------------------------------------------------------------
In testing, even with the patched DLL the plugin could still be
disabled by the host on some machines (reported as a processing
error, with no other message). Importing the plugin's registry
entries on those machines resolved it.

So when distributing the plugin, the registry entries must be
imported in addition to the DLL and the sample content.

----------------------------------------------------------------
1. Which registry entries are read
----------------------------------------------------------------
Key:  HKEY_LOCAL_MACHINE\Software\Steinberg\LM4-MarkII
Values:
    SetupID     REG_SZ      a string of 4 numeric groups
    SetupSysID  REG_BINARY  10 bytes, decoding to a 10-digit number

The plugin also reads Windows' own ProductId (normally no action
needed):
    HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\ProductId
    HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion\ProductId

Code locations (for reference):
    registry wrapper   RVA 0x1F020
    reads SetupID      RVA 0x1EB70 (calls the wrapper at 0x1EBAC)
    reads SetupSysID   RVA 0x1F0B0 (calls the wrapper at 0x1E83D)

----------------------------------------------------------------
2. SetupSysID encoding
----------------------------------------------------------------
SetupSysID is 10 binary bytes; each byte decodes as:

    (b - 8) XOR 1   ->  one character

Reverse:
    (c XOR 1) + 8   per character

----------------------------------------------------------------
3. Verified values (exported directly from a working machine)
----------------------------------------------------------------
Exported on 2026-09-13 from TOLOC-LAPTOP (192.168.3.177) using
`reg export`, where the plugin works correctly:

    SetupID     = 0-0-0-0
    SetupSysID  = 3D 3B 3C 3A 3F 3C 3F 3C 39 3F
                  decodes to "4253656506"

This differs from the value assumed during earlier analysis -- see
section 6.

----------------------------------------------------------------
4. How to import
----------------------------------------------------------------
LM4-MarkII_注册表.reg in this folder contains the values above;
double-click it and confirm the administrator prompt.

Manually: Win+R -> regedit -> navigate to
    HKEY_LOCAL_MACHINE\SOFTWARE\Steinberg\LM4-MarkII
and create the two values.

64-bit Windows note:
    The plugin is 32-bit, so on 64-bit Windows it reads the
    WOW6432Node view, i.e. the effective path is
        HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Steinberg\LM4-MarkII
    The .reg file here writes both views so either system works.

----------------------------------------------------------------
5. Exporting from a working machine
----------------------------------------------------------------
  regedit -> HKEY_LOCAL_MACHINE\SOFTWARE\Steinberg\LM4-MarkII
  (on 64-bit Windows, if that is empty, look under
      HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Steinberg\LM4-MarkII )
  Right-click -> Export -> save as .reg.

From an elevated command prompt:
  reg export "HKLM\SOFTWARE\WOW6432Node\Steinberg\LM4-MarkII" x.reg /y

----------------------------------------------------------------
6. An open point
----------------------------------------------------------------
Earlier analysis (based on data from a different machine) concluded
that SetupSysID should decode to "2523069250":

    3B 3C 3B 3A 39 3F 40 3B 3C 39  ->  "2523069250"

but the value that actually works on TOLOC-LAPTOP is:

    3D 3B 3C 3A 3F 3C 3F 3C 39 3F  ->  "4253656506"

The two differ, and the latter works in practice.

Explanation: the patched DLL already skips the "check failed ->
return NULL" branch in main() (jne -> jmp at 0x1001B968), so the
check result no longer decides whether the plugin loads. The check
function is still called (it also performs initialisation), and the
*absence* of the registry entries versus their *presence* makes it
take different branches -- which is the real cause of the
"disabled on some machines" behaviour.

Conclusion: distribute the value that is verified to work (the one
in section 3). If it still fails on your machine, export your own
values as described in section 5.

----------------------------------------------------------------
7. Other Steinberg plugins on the same machine (for reference)
----------------------------------------------------------------
Same registry layout:

    [HKLM\SOFTWARE\WOW6432Node\Steinberg\Virtual Guitarist]
    SetupID     = 1239765930-1066732172-2494725182-359992275
    SetupSysID  = 38 3E 41 38 3A 3E 38 3A 38 38   ("1781371311")

    [HKLM\SOFTWARE\WOW6432Node\Steinberg\Virtual Guitarist EE]
    SetupID     = 2885539254-1066732172-2494725182-359992275
    SetupSysID  = 3D 38 3B 3A 40 38 3B 39 3D 3B

Note that SetupID is normally four 10-digit groups, whereas LM-4 on
this machine holds "0-0-0-0" (a placeholder written by the installer
or keygen) -- further supporting the idea that the exact value
matters less than the entry simply existing.
